# Marginalia — source-grounded study app

Students put sources (PDF textbooks, pasted text, web pages, YouTube videos, lecture recordings) into a **subject**, then ask questions or request study material. Every answer is generated by Google Gemini **only from retrieved chunks of the sources the student has checked**, with citation markers that jump to the cited passage.

Beyond Q&A it generates study material (recall cards with spaced repetition, quizzes, **IB-style exam questions with examiner marking**, study sheets, concept maps, **summaries**, audio episodes). A subject can be tied to an **IB course** (e.g. Computer Science HL), which makes every generator and the chat follow IB conventions. It covers the core of what NotebookLM and Turbo AI offer, under its own names and design.

## Layout

```
backend/    FastAPI + SQLAlchemy + Postgres/pgvector + Gemini REST API via httpx (Python 3.12, uv)
frontend/   Next.js 16 App Router + Tailwind v4 (client-rendered SPA in components/App.tsx)
  lib/local/  the on-device engine (IndexedDB + Gemini from the device) used by the phone app/PWA
  android/    Capacitor Android project (wraps the static build in out/)
.github/workflows/   android.yml (signed APK → GitHub Release), pages.yml (PWA → GitHub Pages)
android-signing/     APK signing key (gitignored; uploaded as repo secrets)
docker-compose.yml   optional pgvector Postgres for non-embedded setups
```

There are **two engines behind one `api` surface** (`lib/api.ts`), picked at build time by
`NEXT_PUBLIC_ENGINE`: `local` (default; phone/PWA, no server) or `server` (the FastAPI backend on the
laptop; `frontend/.env.local` sets this for `npm run dev`). INSTALL.md is the user-facing phone guide.

## Running

```bash
# backend (port 8000)
cd backend
cp .env.example .env        # then set GEMINI_API_KEY (free from aistudio.google.com)
uv run uvicorn app.main:app --reload --port 8000

# frontend (port 3000)
cd frontend
npm install
npm run dev
```

On-device version: `npm run dev:local` (port 3001, separate `.next-local` dir so it runs beside the
laptop dev server), `npm run build:static [-- --base /repo]` (static export to `out/` + manifest +
service worker), `npx tsx scripts/engine-smoke.mts [--only=pdf,chat] [--audio]` (end-to-end engine check
against real Gemini in Node with fake-indexeddb; reads the key from backend/.env; uses daily quota).

With `DATABASE_URL` empty, the backend starts an **embedded Postgres + pgvector via `pgserver`** (data in `%LOCALAPPDATA%/studyapp-pg` or `~/studyapp-pg`). For a real database: `docker compose up -d db` and set `DATABASE_URL=postgresql://study:study@localhost:5433/study`.

Tests: `cd backend && uv run pytest`. They use the embedded server with a separate `studyapp_test` database (or `TEST_DATABASE_URL`), the offline `HashEmbedder`, and an `httpx.MockTransport` in place of Gemini, so they need no network or API key. `conftest.py` pins `GEMINI_API_KEY` so a developer's `.env` can't change test behaviour. The first run is slow (~1–2 min) while Postgres boots.

## Backend architecture (`backend/app`)

| File | Role |
|---|---|
| `config.py` | `Settings` from env / `.env` (Gemini key/model/base URL, chunk sizes, embedder, k). |
| `models.py` | `Subject` → `Source` → `Chunk`; `Subject` → `Artifact` (deck/quiz/sheet/episode) → `Card` / `QuizAttempt`. `Artifact.passages` freezes the chunks a generator saw (as citation dicts), so `cite: [n]` keeps resolving to `passages[n-1]`. `Source.status` is `ready | processing | failed`. `Source.text` is the full extracted text; `Source.pages` is `[{page,start,end}]` char spans. `Chunk` stores `text`, `char_start/char_end`, `page_start/page_end`, `token_count`, `embedding vector(384)`. |
| `db.py` | Engine/session, embedded-pgserver fallback, `create_schema` (extension + tables + HNSW cosine index + `ALTER … ADD COLUMN IF NOT EXISTS` for columns added later). No Alembic yet. |
| `ingestion/parse.py` | `parse_pdf` (pypdf, per-page spans joined by `\n\n`), `parse_text`, `parse_url` (httpx + BeautifulSoup; PDFs by content-type; private/loopback hosts rejected). All return `ParsedDoc(title, text, pages)`. |
| `ingestion/chunker.py` | Splits into sentence units (word runs / hard slices for oversized ones), packs greedily to ≤ `chunk_tokens` (800) with ~`chunk_overlap_tokens` (120) of trailing units repeated. Token counts use tiktoken `cl100k_base` as a proxy. |
| `ingestion/pipeline.py` | `ingest()` creates a Source and calls `store_chunks()`, which (re)builds chunks + embeddings for a Source (with an optional progress callback). |
| `jobs.py` | Background ingestion for big uploads. Routes stream the file to `data/uploads/`, create the Source as `status="processing"`, and `submit()` a job: a *producer* (file → `ParsedDoc`) then `store_chunks`. Two queues: `media` (1 worker, Whisper) and `docs` (2 workers, PDFs). Progress + stage live in memory (`state()`), exposed as `progress`/`stage` on `SourceOut`. Failures set `status="failed"` + `error`. `resume_pending()` re-queues jobs on startup if the upload is still on disk. |
| `transcribe.py` | Local Whisper via `faster-whisper` (CTranslate2, CPU int8, VAD on). `whisper_producer` loads the model (`WHISPER_MODEL`, default `base`, downloaded once to the Hugging Face cache), enforces `WHISPER_MAX_MINUTES` (120), and groups segments into paragraphs that open with `(mm:ss)` timestamps. Audio is decoded **by us** with PyAV (`decode_windows`: mono 16 kHz float32, 10-minute windows, ~40 MB) and passed to Whisper as arrays. Don't hand faster-whisper a file path: its loader passes `metadata_errors`, which PyAV ≥15 rejects, and it would hold a whole 2 h file (~460 MB) in memory. Loads the model with `local_files_only=True` first, at ≤4 threads. Out-of-memory errors become `RetryableError` (upload kept, Retry button). Measured ~7× real time with `base` on this 8-core laptop (≈18 min per 2 h). |
| `generate.py` | Gemini structured-output generators (`responseSchema`): `build_deck`, `build_quiz`, `build_sheet` (study guide / briefing / FAQ / timeline / key terms), `build_concept_map`, `build_episode` (4 formats × 3 lengths). `select_passages` picks focus-matched chunks, or chunks spread evenly through each checked source. `synthesize_episode` renders speech via the **Interactions API** (`POST /interactions`, model `GEMINI_TTS_MODEL`, one text item per line with a `speech_metadata` speaker annotation, l16 24 kHz → WAV). `transcribe_audio`/`transcribe_youtube` use Gemini for short clips and YouTube URLs. |
| `ib.py` | IB Diploma conventions: the official **command terms** with definitions grouped by objective level (1 knowledge & understanding, 2 application & analysis, 3 synthesis & evaluation), the course list, `context(subject)` (a system-prompt addendum added to **every** generator and the chat when `Subject.ib_course` is set), and `MARKING_RULES`: positive whole-mark marking, OWTTE, no double credit, command-term-aware, ECF, best-fit markbands, capped at the total. Based on secondary sources (command-term glossaries, IB assessment guide); the subject guide on the IB Programme Resource Centre is the authority. |
| `exams.py` | IB-style question sets (`build_exam`): command term first, mark value, objective-1 items then structured items, an optional extended item with **markbands** + indicative content; analytic markschemes list creditworthy points `[n]` (more points than marks allowed) + accept/reject `notes`. `clean_question` normalises command terms and validates. `draft_markscheme` writes a markscheme for a student-supplied/past-paper question. `mark_answer` marks per point (each capped at its value, total capped) or by band; blank answers get 0. |
| `summarize.py` | Summaries in 4 formats (key points, Cornell notes, IB revision notes, narrative) × 3 lengths. `summary_passages` = all chunks of the chosen sources in reading order (optional PDF **page range**, max ~700 chunks) or focus-retrieved ones. Inputs under `SINGLE_PASS_TOKENS` (60k) take one request. Larger ones are **map-reduced**: notes per ~40k-token batch, then a combining pass. Passages are numbered globally so `[n]` citations survive. |
| `vision.py` | Gemini image reading for **photos of handwritten work** (≤6 photos, ≤10 MB each; the frontend shrinks them to ≤1800 px JPEG). `read_answer` transcribes **verbatim**, keeping spelling and grammar because the text is then marked. Given the question, it picks out just that answer from a page of several, matching by topic. `read_question` reads a past-paper question + `[marks]`. `read_quiz_answers` reads a numbered answer sheet: MCQ letters → option indexes, written answers → verbatim text. Routes: `POST /vision/answer`, `/vision/question`, `/artifacts/{id}/quiz-photo`. |
| `srs.py` | SM-2-style scheduling with four grades (again/hard/good/easy). "Again" returns in 10 min. `preview()` gives the button labels ("1d", "2w"). |
| `study_routes.py` | `/subjects/{id}/artifacts` (list/generate; kinds deck, quiz, sheet, episode, exam, summary), `/artifacts/{id}` (+ `/review`, `/reset`, `/attempts`, `/audio`, `/questions/{i}/mark`), `/cards/{id}/review`, `/subjects/{id}/exam/custom`, `/ib/options`. **All generation runs in the background** (`_start_generation` → `_gen_pool`, 2 workers): the POST returns at once with a placeholder whose `Artifact.status` is `processing`, then `ready` or `failed` + `error`. `progress`/`stage` are kept in memory. This lets generation survive the student leaving the screen or reloading. Startup marks leftover `processing` artifacts failed. The frontend (`useArtifacts`) polls while anything is processing, shows `JobStatus` rows, can open an item when it finishes (`openWhenReady`), and broadcasts `marginalia:artifacts-changed` so a re-mounted screen picks up a request that finished after it was left. Exam answers are stored as `QuizAttempt.answers=[{q, answer, result}]`; `marked` in the detail = the latest per question. |
| `embeddings.py` | `FastEmbedEmbedder` (local ONNX `BAAI/bge-small-en-v1.5`, downloads once) or `HashEmbedder` (`EMBEDDER=hash`). Both 384-d, normalised. Changing dimension requires recreating the `chunks` table. |
| `retrieval.py` | `retrieve(db, subject_id, source_ids, query_vec, k)` returns cosine top-k, filtered by subject **and** the explicit source id list. Empty list → no results (never "search everything"). |
| `chat.py` | `ChatRequest` schema, `retrieval_query`, `sse` framing. |
| `gemini.py` | Builds the Gemini request, streams it (REST `models/{model}:streamGenerateContent?alt=sse`, `x-goog-api-key` header) and turns `[n]` markers into citation events. See below. |
| `main.py` | REST routes + SSE chat endpoint. At import it calls `truststore.inject_into_ssl()` (use the Windows/macOS trust store: school networks inspect HTTPS with their own root CA, which Python's bundled list rejects) and sets `HF_HUB_DISABLE_XET=1` (Xet model transfers stall on some networks; plain HTTP works). |

### Sources and size limits

| Input | Route | Limit | How |
|---|---|---|---|
| PDF | `POST …/sources/pdf` → 202 | 600 MB | Streamed to disk, background job: pypdf page by page (bad pages skipped), then indexing |
| Recording (any audio/video format) | `POST …/sources/recording` → 202 | 2 GB / 2 h | Background Whisper job on this machine. Roughly 10–20 min per 2 h with `base` on 8 cores |
| Short clip via Gemini | `POST …/sources/audio` | 18 MB | Inline Gemini transcription with headings. Uses quota. Not used by the UI now |
| YouTube URL | `POST …/sources/url` | — | Detected by `YOUTUBE_RE`; Gemini transcribes from `fileData.fileUri` |
| Web page / text | `…/url`, `…/text` | — | Synchronous |

### Invariants worth protecting

- **`chunk.text == source.text[chunk.char_start:chunk.char_end]`**. Citations and Read-mode highlighting depend on it. Tests assert it.
- Retrieval only ever touches checked sources of the current subject. A Read-mode highlight also adds its own source even if unchecked.
- Source text is normalised once at parse time. Never re-normalise later, or offsets drift.

### Chat / citations flow

1. `POST /subjects/{id}/chat` takes `{message, source_ids, selection?, history?}`.
2. The query embedding is `selection.text + message` when there's a highlight.
3. Retrieved chunks are numbered and sent as `<passage n="1" source="Title, p. 4">…</passage>` blocks in the final user turn, followed by the question (wrapped in `<highlight>` when present). Prior turns go in `contents` as plain text (`assistant` → `model`). `systemInstruction` tells Gemini to answer only from the passages and cite them as `[n]`.
4. Gemini has no document-citation feature, so `CiteParser` scans the streamed text for `[n]` / `[1, 3]` markers. It emits the text before a marker as `{"type":"text"}` and the marker as `{"type":"cite","citations":[…]}`. It holds back a partial `[1` across chunk boundaries and leaves out-of-range numbers such as `[1919]` as text. **A citation spans the whole chunk** (`chunk.char_start..char_end`), not the exact sentence.
5. The stream ends with `{"type":"done"}` or `{"type":"error"}`. Errors cover a missing/invalid key, a 429 free-tier rate limit, a 404 wrong `GEMINI_MODEL`, a `promptFeedback.blockReason`, or a SAFETY finish. A `MAX_TOKENS` finish appends a "cut off" note.

SSE frames are `data: <json>` followed by a blank line. The first event is always `{"type":"sources"}` (what was retrieved). `GET /health` reports the model and whether a key is configured.

Settings: `GEMINI_API_KEY`, `GEMINI_MODEL` (default `gemini-3.8-flash`; change it if Google retires that model), `GEMINI_FALLBACK_MODEL` (default `gemini-3.5-flash`). On 500/503 the request is retried twice with backoff, then sent to the fallback model, `GEMINI_BASE_URL` (default `https://generativelanguage.googleapis.com/v1beta`).

**Free-tier tuning.** Defaults are a middle ground for Google's free tier, whose real per-project limits are only visible at aistudio.google.com/rate-limit:
- `RETRIEVAL_K=12` passages per question (~10k input tokens).
- `GEMINI_MAX_TOKENS=32768` output cap, which includes thinking. Only tokens actually produced count.
- `GEMINI_RPM=8`: a process-wide `Pacer` (sliding 60s window) keeps requests under the per-minute cap. If no slot frees up within `GEMINI_MAX_QUOTA_WAIT` (20s), the user gets an error instead of a hang.
- **Dropped connections** (`httpx.TransportError`, common on school networks and long answers) are retried twice by `generate_json`.
- On 429, `quota_info` reads Google's `RetryInfo.retryDelay` and `QuotaFailure.quotaId`. A per-minute limit with a short delay is waited out and retried. A per-day limit (`…PerDay…`) skips retries and goes straight to the fallback model, since free quotas are counted per model. If both models are exhausted, the user is told it resets at midnight Pacific time.

## Frontend architecture (`frontend/`)

The UI is **mode-based, not paneled**. One main surface at a time, switched from a slim left rail (Alt+1–5: Library, Read, Summarise, Practice, Listen):

- **Library** (`LibraryMode.tsx`): subject switcher/creation, add source (PDF drop / paste / link), source cards whose checkbox controls `Source.checked` (= "in play for answers").
- **Read** (`ReadMode.tsx`): one source full-width in a reading column. Text is split into paragraphs and spans that carry `data-o` (absolute char offset), so a DOM selection maps back to source offsets (`absOffset`). Selecting text opens an anchored **margin thread** (`MarginThread.tsx`) placed level with the passage. Cards are pushed down to avoid overlap (`MarginColumn` layout effect). On narrow screens the active thread floats above the command bar.
- **Library** also has a **Study sheets** view (`SheetsPanel.tsx`): study guide, briefing, FAQ, timeline, key terms, and a collapsible **concept map** tree. Inline `[n]` markers become citation chips via `lib/cite.ts`. The add-source box takes PDF / text / link-or-YouTube / lecture audio (record in the browser via `MediaRecorder`, or upload). Uploads use XHR for an upload progress bar. Processing sources show stage + progress, and `App.tsx` polls every 3 s while any source is processing.
- **Summarise** (`SummariseMode.tsx`, rail Alt+3): pick sources (chips) or paste text (saved as a source so citations work), optional page range (single PDF) or topic, format + length. Shows background progress, a viewer with citations, and copy/print. The Library header has an **IB course + SL/HL picker** (`IBCoursePicker`). An `IBBadge` shows "Written for IB …" in Summarise and Practice.
- **Quizzes** mix three types, picked as a multi-select: multiple choice, short answer (`accept` list of acceptable wordings) and written explanation (`marks` + markscheme `points`). Old untyped questions are treated as MCQ. `QUIZ_SCHEMA` makes **every field required** (non-applicable ones are `[]`/0), because Gemini drops optional fields and MCQs came back without options. `split_count` shares the count across types. `exams.mark_quiz` marks MCQ and normalised exact short answers locally; all other short and written answers go to Gemini in **one** batched request (lenient on synonyms and misspellings for short answers, per-point capped for written ones). The attempt response has `results[]` per question.
- **Photo buttons** (`PhotoButton.tsx`): "Photo of my answer" on every exam question, photos of the question and the answer in "Mark my question", and "Photo of my answers" in quizzes. The text lands in the answer box for the student to check before marking.
- **Practice** (`PracticeMode.tsx`): **Exam questions** (`ExamPractice.tsx`): make an IB-style set (~15/30/50 marks, optional extended response), answer each question, "Mark my answer" → marks, ✓/✗ per markscheme point with comments, chosen markband, strengths, how to reach full marks, and a full-mark answer. The markscheme stays hidden until marked (or peeked). "Mark my question" takes a pasted past-paper or teacher question + marks, drafts a markscheme from your sources, and marks your answer. **Recall cards**: make a deck (focus, 10/15/25 cards), review due cards (Space to reveal, 1–4 to grade, "again" re-queues in-session), browse, restart. **Quizzes**: Recall/Understand/Apply difficulty, 5/8/12 questions, check answers → score, explanations, citations, retake.
- **Listen** (`ListenMode.tsx`): episodes in four formats (Talk-through, Quick brief, Debate, Mini-lecture), ~3/7/11 min, optional steering. The player uses **device voices** (Web Speech API, free, line-by-line with two voices) or **studio audio** (Gemini TTS WAV, rendered on demand, uses quota). The transcript highlights the current line and is clickable to seek. Lines carry citations.
- **Try again everywhere Gemini can fail** (overload, quota, dropped connection): failed generations show `JobStatus` + `RetryLink`, which calls `POST /artifacts/{id}/retry`. That re-runs `_generate` with the stored `params` **in place** (`reuse=`): the same row and id, old cards cleared, no duplicates. Generator forms resend the last request (`useArtifacts.retryLast`). Chat errors re-ask the last question (`forRetry` in `lib/threads.ts`). Exam/quiz marking, "Mark my question", studio audio, photo reading (`PhotoButton` keeps the last photos) and adding sources (`lastRun` in `AddSource`) all pass `onRetry` to `ErrorNote`. "Can't reach the API" reloads the page.
- Shared study UI lives in `components/study/shared.tsx` (`useArtifacts`, `CiteMarks`, `Segmented`, `Working`).
- **Command bar** (`CommandBar.tsx`, "Ask or make…", `/` to focus, a "Make" button for quick generation prompts). In Read mode it posts into the active margin thread, or a new unanchored one. In other modes the answer rises in a `ResponseSheet`.
- **Citations**: answers are stored as text with `⟦n⟧` tokens (`lib/threads.ts`). `AnswerBody.tsx` is a tiny streaming-safe Markdown subset that turns tokens into numbered markers. Clicking one switches to Read, loads the source, scrolls to the span and flashes it (`Focus` in `App.tsx`).

State lives in `App.tsx` (no global store). Threads are in-memory only and are **not persisted** in this MVP.

`NEXT_PUBLIC_API_URL` (default `http://localhost:8000`) points the browser straight at FastAPI. CORS is configured via `CORS_ORIGINS`. Streaming goes direct, not through a Next proxy, to avoid buffering.

## On-device engine (`frontend/lib/local/`, phone app + PWA)

A TypeScript port of the backend that runs in the WebView/browser. `store.ts` exposes `localApi` with the
same methods and response shapes as the REST API, plus `exportBackup`/`importBackup`/`dueCards`/`audioSrc`.

| File | Role |
|---|---|
| `db.ts` | Dexie (IndexedDB) schema mirroring the Postgres tables. v2 adds a global `uid` + `updated_at` on synced tables (subjects, sources, artifacts, cards, attempts), stamped by Dexie hooks (an update that sets `updated_at` itself, i.e. a sync write, keeps it), and `tombstones` written by the store's delete paths; `blobs` holds pending uploads (`upload-<sourceId>`) and studio audio (`episode-<id>`). |

Free-tier reality: the main model allows ~20 requests/day; the smoke test alone can use most of it.

## Design constraints

- Must **not** resemble NotebookLM: no three-column sources/chat/studio layout, no borrowed feature names ("Notebook", "Studio", "Audio Overview", …), no Google-style blue/white look. Current identity: "Marginalia", warm paper/ink palette, terracotta accent, Fraunces display + Literata reading + Public Sans UI.
- Keep the mode-switch model: new features become modes or overlays, not permanent side panels.

## Known gaps / next steps

- Not built yet (equivalents exist in NotebookLM/Turbo): video overviews, slide decks, infographics, web source discovery, collaboration/sharing, editable notes, interactive "join the conversation" audio.
- Jobs are in-process threads. For multi-user deployment move them to a real queue (RQ/Celery/arq). Progress is lost on restart; the job itself is re-queued.
- Whisper runs on CPU. If a GPU is available, `device="cuda"` in `transcribe._model` is ~10× faster.
